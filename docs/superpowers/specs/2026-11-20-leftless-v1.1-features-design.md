# Leftless 1.1 — Batch Uninstall, Orphaned Leftovers, Trash Watch, App Reset: Design

Date: 2026-11-20 · Status: approved by user in chat · Builds on the 2026-11-19 and 2026-11-20 specs (all §4 anti-goals still bind: nothing pre-ticked that may belong to another app or the system, never touch `com.apple.*`/SIP paths, nothing permanently deleted, manifest written before any move, no technical jargon in the main UI).

## Order (user): batch uninstall → orphaned leftovers → Trash watch → app reset → release v1.1.0

## 1. Batch uninstall
- Sidebar allows multi-selection (⌘/⇧-click). With ≥2 apps selected, the detail shows one section per app (header: icon, name, selected size) with that app's grouped leftovers and checkboxes, and one **Move to Trash** button.
- One confirmation dialog for all (e.g. "3 apps and 41 items will be moved to the Trash (1.2 GB)"), one quit prompt listing running apps, **one password prompt** for all admin items.
- History: **one record per app** so each can be restored alone.
- Single selection behaves exactly as today.

## 2. Orphaned leftovers
- New toolbar tab: `Apps | Leftovers | History (N)`; ⌘1/⌘2/⌘3.
- A scan lists Library items that belong to **no app on this Mac**. "On this Mac" = /Applications, ~/Applications (2 levels), Apple apps (/System/Applications) and every app Spotlight knows (`mdfind kMDItemContentType == 'com.apple.application-bundle'`).
- v1 only considers entries whose name is a reverse-DNS identifier (e.g. `com.vendor.app`, `com.vendor.app.plist`, `TEAMID.com.vendor.app` in Group Containers) in the user's Library locations (Application Support, Caches, Preferences, Containers, Group Containers, Saved Application State, HTTPStorages, WebKit, Cookies, Logs, LaunchAgents), plus LaunchAgents whose program no longer exists.
- An entry is **owned** (never listed) if it is protected/Apple, or matches any known app's bundle ID exactly, as a dotted prefix, or shares its vendor prefix (`com.vendor.`) with a known app.
- Results grouped by identifier root (first three components, e.g. `com.vendor.app`) with total size, sorted by size. **Nothing pre-ticked**; a "Select All" button. Without Full Disk Access, Containers/Group Containers are skipped and the banner says so.
- Moving them to the Trash creates one history record titled "Orphaned leftovers" (restorable as usual).

## 3. Trash watch
- New **Settings** window (⌘,) with "Watch the Trash for deleted apps" — **off by default**.
- Turning it on: asks notification permission and registers Leftless as a login item (`SMAppService.mainApp`); when launched at login, Leftless starts without a window.
- While running (window or not), Leftless watches `~/.Trash`. When a new `.app` appears there, it scans that app's leftovers (excluding the app bundle itself) and, if any are found, posts a notification: "SoundWave left 14 items (85 MB)" with a **Clean Up** action. Clicking it opens Leftless showing that app's leftovers for review (nothing moves without the usual confirmation).
- Requires Full Disk Access to read the Trash; the setting explains this and is disabled without it.
- Turning it off unregisters the login item and stops watching.

## 4. App reset
- In an app's detail, a **Reset…** button next to Move to Trash.
- Reset selects only the app's *data*: certain items of kinds Application Support, Caches, Preferences, Logs, Saved State, HTTP Storage, WebKit Data, Cookies, Container, Group Container. The app, launch agents/daemons, helpers, plug-ins, installer files and possible matches stay.
- Confirmation shows what will be cleared; the app is quit first if running; history record marked "Reset".

## Core changes (decided)
- `HistoryRecord.operation: HistoryOperation` (`uninstall`, `reset`, `orphans`), decoding to `uninstall` when absent (old records).
- `Uninstaller.uninstall(batch:)` processes several (scan, selected, icon, operation) jobs with one privileged run; the existing single-app API delegates to it.

## Non-goals
Homebrew/CLI tools, system extensions removal, scheduled scans, menu-bar app, non-reverse-DNS orphan names.

## Left to the builder
Exact layout, wording, and how the multi-app detail scrolls.
